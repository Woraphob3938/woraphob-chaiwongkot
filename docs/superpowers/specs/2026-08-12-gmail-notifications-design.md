# สเปกระบบแจ้งเตือน FitConnect ผ่านหน้าเว็บและ Gmail

วันที่: 12 สิงหาคม 2026  
สถานะ: อนุมัติแล้วเมื่อ 12 สิงหาคม 2026

## 1. เป้าหมายและขอบเขต

เพิ่มศูนย์การแจ้งเตือนสำหรับสมาชิกและเทรนเนอร์ โดยเก็บการแจ้งเตือนใน FitConnect และส่งเหตุการณ์สำคัญไปยังอีเมลที่ใช้สมัครบัญชีผ่าน Gmail SMTP

งานนี้ครอบคลุมเฉพาะเหตุการณ์ที่มีอยู่แล้วในระบบ ได้แก่ การจอง การชำระเงิน การหมดเวลา การยกเลิก และการเตือนก่อนนัด ไม่เพิ่มขั้นตอนให้เทรนเนอร์กดรับการจอง ไม่เพิ่มจังหวัดหรือสถานที่นัดฝึก และไม่ส่งไฟล์สลิปหรือเอกสารรับรองไปกับอีเมล

ผู้ดูแลระบบยังตรวจสลิปด้วยตนเองตาม workflow เดิม การแจ้งเตือนไม่เปลี่ยนสถานะการจองหรืออนุมัติรายการใดแทนผู้ดูแลระบบ

## 2. แนวทาง UI ที่เลือก

ใช้แบบที่ 4: Master Detail Feed และคงระบบภาพ Athlete Credential ของ FitConnect

### Desktop

หน้า `/notifications` แบ่งเป็นสามส่วนภายในพื้นที่เนื้อหา:

1. หมวดแจ้งเตือน: ทั้งหมด การจอง การชำระเงิน และนัดหมาย พร้อมจำนวนที่ยังไม่ได้อ่าน
2. รายการแจ้งเตือน: ชื่อ เหตุการณ์ เวลาที่เกิด สถานะอ่านแล้ว และรหัสการจองเมื่อเกี่ยวข้อง
3. รายละเอียด: ข้อความเต็ม ข้อเท็จจริงของการจอง ประวัติสถานะที่เกี่ยวข้อง และปุ่มหลักหนึ่งรายการ

sidebar หลักเพิ่มเมนู `การแจ้งเตือน` สำหรับสมาชิกและเทรนเนอร์ พร้อม badge จำนวนที่ยังไม่ได้อ่าน ผู้ดูแลระบบไม่อยู่ในขอบเขตรอบนี้

### Tablet และมือถือ

- หมวดเปลี่ยนเป็นแถบเลื่อนแนวนอนหนึ่งบรรทัด
- รายการแจ้งเตือนแสดงเต็มความกว้าง
- เมื่อเลือกรายการ ระบบแสดงรายละเอียดในหน้าเดียวกันและมีปุ่ม `กลับรายการแจ้งเตือน`
- ไม่ใช้ modal ซ้อนหลายชั้นและไม่สร้าง sidebar ชุดที่สอง
- หน้าต้องไม่เกิด horizontal overflow ที่ 320, 375, 414, 768 และ 1280 พิกเซล

### การใช้งาน

- กดรายการเพื่ออ่านและเลือกเป็นรายการปัจจุบัน
- กด `ทำเครื่องหมายว่าอ่านแล้วทั้งหมด` ได้
- กรอง `ทั้งหมด` หรือ `ยังไม่ได้อ่าน` ได้
- แบ่งหน้าฝั่ง API ครั้งละ 10 รายการ เพื่อไม่ให้หน้าและการตอบกลับโตตามจำนวนข้อมูลทั้งหมด
- ปุ่มหลักพาไปยังหน้าที่มีอยู่แล้ว เช่น `/member`, `/trainer`, `/chat` หรือหน้ารายละเอียดการจองที่ระบบใช้งานอยู่
- ใช้ข้อความ ไอคอน และตำแหน่งร่วมกันเพื่อบอกสถานะ ไม่พึ่งสีเพียงอย่างเดียว

### เทรนเนอร์

| เหตุการณ์ | แจ้งในเว็บ | ส่ง Gmail | ปุ่มหลัก |
|---|---:|---:|---|
| หลักฐานผ่านและมีการจองที่ยืนยันแล้ว | ใช่ | ใช่ | ดูนัดหมาย |
| การจองที่ยืนยันแล้วถูกยกเลิก | ใช่ | ใช่ | ดูตาราง |
| นัดหมายจะเริ่มใน 24 ชั่วโมง | ใช่ | ใช่ | ดูนัดหมาย |

เทรนเนอร์ไม่รับแจ้งเตือนตอนสมาชิกเพิ่งเลือก slot หรือยังอยู่ในช่วงชำระเงิน เพราะยังไม่ใช่การจองที่ยืนยันแล้ว และไม่มีขั้นตอนให้เทรนเนอร์กดรับคำขอ

แชตและรีวิวไม่ส่ง Gmail ในรอบนี้เพื่อไม่ให้เกิดอีเมลจำนวนมากและไม่ขยายเกินขอบเขตที่ตกลงไว้

## 4. โครงสร้างข้อมูล

เพิ่มตาราง `notifications`:

| ฟิลด์ | หน้าที่ |
|---|---|
| `id` | รหัสภายใน |
| `recipient_user_id` | สมาชิกหรือเทรนเนอร์ผู้รับ |
| `type` | ประเภทเหตุการณ์ที่กำหนดไว้ในระบบ |
| `category` | `booking`, `payment` หรือ `appointment` |
| `title` | หัวข้อภาษาไทยแบบสั้น |
| `message` | คำอธิบายที่แสดงในหน้าและอีเมล |
| `booking_id` | FK ไปยังการจองเมื่อเกี่ยวข้อง |
| `action_path` | เส้นทางภายใน FitConnect ที่กดต่อได้ |
| `read_at` | เวลาที่อ่านแล้ว หรือ `NULL` |
| `email_status` | `pending`, `sent`, `failed` หรือ `skipped` |
| `email_attempt_count` | จำนวนครั้งที่ลองส่ง |
| `email_next_attempt_at` | เวลาที่อนุญาตให้ลองส่งใหม่ |
| `email_sent_at` | เวลาที่ Gmail รับข้อความแล้ว |
| `email_last_error` | ข้อผิดพลาดแบบตัดข้อมูลลับออก |
| `created_at` | เวลาสร้างรายการ |

ข้อกำหนดเพิ่มเติม:

- สร้าง unique key จากผู้รับ ประเภทเหตุการณ์ และการจอง เพื่อกันอีเมลหรือรายการซ้ำจาก scheduler
- ไม่คัดลอกอีเมลผู้รับลงตาราง ใช้ `users.email` ตอนส่ง
- ไม่เก็บ Gmail App Password ในฐานข้อมูล
- FK ของ `recipient_user_id` ใช้ `ON DELETE CASCADE` เมื่อมีการลบแถวผู้ใช้จริง ส่วนบัญชีที่เปลี่ยนเป็นสถานะ suspended หรือ deleted แบบ soft delete ยังคงประวัติ notification ไว้

## 5. Gmail SMTP

ระบบส่งจากบัญชี Gmail กลางของ FitConnect โดยผู้ดูแลเครื่องเปิด 2-Step Verification และสร้าง App Password

ค่าที่เพิ่มใน `backend/.env`:

```env
MAIL_ENABLED=false
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=
MAIL_APP_PASSWORD=
MAIL_FROM_EMAIL=
MAIL_FROM_NAME=FitConnect
APP_URL=http://localhost:3000
```

ข้อกำหนดการส่ง:

- ใช้ PHP cURL SMTP ที่ XAMPP มีอยู่แล้ว จึงไม่เพิ่ม Composer หรือไลบรารีส่งอีเมลใหม่
- ใช้ STARTTLS และตรวจ certificate ตามค่า cURL ปกติ
- หัวข้อขึ้นต้นด้วย `[FitConnect]`
- ส่งทั้งข้อความธรรมดาและ HTML แบบเรียบ
- escape ข้อมูลชื่อผู้ใช้ รหัสการจอง และข้อความทุกครั้ง
- ลิงก์ใช้ `APP_URL` และชี้เฉพาะเส้นทางภายใน FitConnect
- ไม่แนบสลิป รูปโปรไฟล์ ใบรับรอง หรือ token

## 6. ลำดับการบันทึกและการส่ง

1. Business transaction เปลี่ยนสถานะการจองหรือการชำระเงิน
2. ใน transaction เดียวกัน ระบบเพิ่ม notification พร้อม `email_status = pending` หรือ `skipped`
3. หลัง commit ระบบลองส่งรายการ pending ทันที
4. หาก Gmail ใช้งานไม่ได้ การทำรายการหลักยังสำเร็จและ notification ในเว็บยังคงอยู่
5. scheduler ลองส่งรายการ pending หรือ failed ที่ถึงเวลาอีกครั้ง สูงสุด 5 ครั้ง
6. เมื่อครบ 5 ครั้ง ระบบคงสถานะ failed ไว้ให้ตรวจ log โดยไม่แสดงรายละเอียดระบบแก่ผู้ใช้

scheduler ใช้รูปแบบเดียวกับงานหมดเวลาการจองของ XAMPP และทำงานทุกหนึ่งนาที ไม่เปิดหน้าต่าง PowerShell หรือ PHP ขึ้นมารบกวนผู้ใช้

## 7. API

เส้นทางใหม่ต้องใช้ Bearer token และอ่านได้เฉพาะ notification ของบัญชีปัจจุบัน:

- `GET /v1/notifications?page=0&category=all&unread=false`
- `GET /v1/notifications/{id}`
- `PATCH /v1/notifications/{id}/read`
- `POST /v1/notifications/read-all`

ผลรายการประกอบด้วยจำนวน unread แยกตามหมวด จำนวนทั้งหมด pagination และรายการ 10 แถว หน้ารายละเอียดไม่ส่งอีเมล ข้อผิดพลาด SMTP หรือข้อมูลบัญชีอื่น

## 8. รูปแบบอีเมล

อีเมลทุกฉบับมี:

1. หัวข้อเหตุการณ์หนึ่งบรรทัด
2. ชื่อผู้รับ
3. รหัสการจอง วันที่ เวลา สถานะ และค่าฝึกเมื่อจำเป็น
4. คำอธิบายขั้นถัดไป
5. ปุ่มหรือลิงก์กลับ FitConnect หนึ่งรายการ
6. ข้อความท้ายว่าอีเมลนี้เป็นการแจ้งเตือนจากระบบ

ไม่มีจังหวัด สถานที่นัดฝึก ข้อความโฆษณา หรือคำอ้างว่าอนุมัติอัตโนมัติ

## 9. สถานะผิดพลาดและการเข้าถึง

- Loading ใช้ skeleton และ polite live region
- โหลดไม่สำเร็จใช้ `role="alert"` พร้อมปุ่มลองใหม่
- รายการว่างอธิบายว่าไม่มี notification ในหมวดที่เลือกและมีปุ่มกลับไปดูทั้งหมด
- badge จำนวน unread มีชื่อที่โปรแกรมอ่านหน้าจอเข้าใจ เช่น `มีการแจ้งเตือนที่ยังไม่ได้อ่าน 3 รายการ`
- รายการใช้ heading และ time element ที่อ่านออกเสียงได้
- ปุ่มไอคอนมีชื่อ, touch target อย่างน้อย 44 พิกเซล และ focus ring ตาม DESIGN.md
- การเปลี่ยนรายการใช้ motion 150 ถึง 200 มิลลิวินาทีและหยุดเมื่อเปิด reduced motion
- เมื่อทำเครื่องหมายว่าอ่านแล้ว ระบบประกาศผลครั้งเดียว ไม่ประกาศตัวเลขซ้ำต่อเนื่อง

## 10. การตรวจสอบ

### Automated

- ทดสอบกติกาว่าแต่ละเหตุการณ์สร้างผู้รับ ประเภท ข้อความ และ Gmail ถูกต้อง
- ทดสอบว่าเทรนเนอร์ไม่ถูกแจ้งก่อนการชำระเงินผ่าน
- ทดสอบ unique key ป้องกัน reminder และอีเมลซ้ำ
- ทดสอบ SMTP disabled, success, retry และ failed โดยไม่ส่ง Gmail จริง
- ทดสอบ API ปฏิเสธการอ่าน notification ของบัญชีอื่น
- ทดสอบ pagination, filter, read, read-all และ unread badge
- ทดสอบ sidebar แสดงเมนูเฉพาะสมาชิกและเทรนเนอร์ตามขอบเขตนี้

### Live และ Browser

- smoke กับ XAMPP ตรวจแถว `notifications` และสถานะ email โดยตั้ง `MAIL_ENABLED=false`
- การส่ง Gmail จริงเป็นคำสั่งแยกที่ต้องระบุอีเมลปลายทางและยืนยันก่อนรัน เพื่อไม่ส่งอีเมลจากชุดทดสอบอัตโนมัติ
- ตรวจหน้า `/notifications` ที่ 320, 375, 414, 768 และ 1280 พิกเซล รวม keyboard, focus, 200% zoom, reduced motion และ horizontal overflow

## 11. สิ่งที่ไม่ทำในรอบนี้

- LINE Notify, push notification, SMS หรือ browser push
- Gmail OAuth ของสมาชิกและเทรนเนอร์
- marketing email, newsletter หรืออีเมลแชตทุกข้อความ
- หน้าจอแจ้งเตือนของผู้ดูแลระบบ
- ระบบตั้งค่ารายหมวดแบบซับซ้อน
- ข้อมูลจังหวัดหรือสถานที่นัดฝึก

## 12. เกณฑ์ส่งมอบ

- สมาชิกและเทรนเนอร์เปิดหน้าแจ้งเตือนจาก sidebar และเห็น unread badge ที่ตรงกับฐานข้อมูล
- รายการจำนวนมากยังแสดงครั้งละ 10 รายการและไม่ทำให้หน้าเลื่อนยาวผิดปกติ
- เหตุการณ์ตามตารางสร้าง notification ถูกผู้รับเพียงครั้งเดียว
- Gmail ส่งผ่านบัญชีกลางเมื่อเปิด `MAIL_ENABLED=true`
- Gmail ล้มเหลวไม่ทำให้การจองหรือการตรวจชำระเงินย้อนกลับ
- เทรนเนอร์ไม่มีปุ่มรับการจองและไม่ถูกแจ้งก่อนสถานะยืนยัน
- UI ไม่มีข้อมูลจังหวัดหรือสถานที่นัดฝึก และยังเป็น FitConnect visual system เดิม
