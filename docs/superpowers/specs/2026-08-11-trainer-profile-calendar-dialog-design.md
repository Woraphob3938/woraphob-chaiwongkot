# FitConnect: โปรไฟล์เทรนเนอร์และปฏิทินเลือกเวลา

วันที่อนุมัติแนวทาง: 11 สิงหาคม 2026
แนวทางที่อนุมัติ: แบบ A

## 1. เป้าหมาย

- ลดขนาดรูปโปรไฟล์และชื่อเทรนเนอร์ เพื่อให้ข้อมูลสำคัญอยู่ในจอแรกมากขึ้น
- เปลี่ยน “ตารางว่างทั้งหมด” จาก disclosure ยาวเป็น Dialog กลางจอ
- ให้สมาชิกเลือกวันจากปฏิทิน แล้วเลือกเวลาว่างของวันนั้น
- หลังยืนยันเวลา Dialog ปิดและหน้าโปรไฟล์แสดงวันกับเวลาที่เลือก
- คงหน้าตรวจรายละเอียดและการยืนยันสร้างการจองเดิม

## 2. ขอบเขต

### อยู่ในขอบเขต

- หน้าโปรไฟล์เทรนเนอร์
- แผงเลือกเวลาฝึก
- Dialog ปฏิทินและรายการเวลาว่าง
- สถานะสรุปเวลาที่เลือกและคำสั่งเปลี่ยนเวลา
- Responsive, keyboard, focus, reduced motion และ empty state

### อยู่นอกขอบเขต

- API, PHP, XAMPP, ฐานข้อมูล และโครงสร้างตาราง
- กติกาการหมดเวลาชำระ 10 นาที
- ขั้นตอนอัปโหลดสลิปและการตรวจโดยแอดมิน
- การเพิ่มสถานะการจองหรือการรับการจองโดยเทรนเนอร์
- จังหวัด พื้นที่ให้บริการ และสถานที่นัดฝึก
- เมนู Sidebar และหน้าอื่น

## 3. สัดส่วนหน้าโปรไฟล์

เดสก์ท็อปยังใช้สามส่วนเดิม ได้แก่รูปเทรนเนอร์ ข้อมูลโปรไฟล์ และแผงจอง แต่ลดน้ำหนักของรูปและหัวข้อดังนี้

- คอลัมน์รูปประมาณ 26% จากเดิมประมาณ 31%
- คอลัมน์ข้อมูลโปรไฟล์ประมาณ 44%
- คอลัมน์แผงจองประมาณ 30%
- ความสูงรูปบนเดสก์ท็อปลดจาก 36rem เหลือประมาณ 28rem
- ชื่อเทรนเนอร์ใช้ขนาดแบบ fluid โดยมีเพดานประมาณ 3.5rem
- เนื้อหาเดิม ได้แก่สถานะตรวจ คุณสมบัติ ราคา รีวิว และใบรับรอง ยังคงอยู่ครบ

บนแท็บเล็ตให้รูปกับข้อมูลอยู่สองคอลัมน์และแผงจองอยู่แถวถัดไป บนมือถือเรียงรูป ข้อมูล และแผงจองเป็นคอลัมน์เดียว รูปมีความสูงประมาณ 20rem โดยไม่ตัดใบหน้าหรือทำให้หน้าเกิด horizontal overflow

## 4. ปุ่มเปิดปฏิทิน

แผงจองแสดงปุ่ม “ดูตารางว่างทั้งหมด” พร้อมจำนวนช่วงที่พร้อมจอง ปุ่มนี้แทน disclosure เดิมและเปิด Dialog กลางจอ

- มีเวลาว่าง: ปุ่มเปิดใช้งานและแสดงจำนวนช่วง
- ไม่มีเวลาว่าง: ปุ่ม disabled พร้อมข้อความ “ยังไม่มีเวลาว่างให้จอง”
- ยังไม่เลือกรอบ: CTA หลักด้านล่างแสดง “เลือกเวลาก่อน” และ disabled
- เลือกรอบแล้ว: แสดงสรุปวันและเวลา พร้อมปุ่ม “เปลี่ยนเวลา”

## 5. Dialog ปฏิทิน

Dialog ใช้คอมโพเนนต์ Radix/shadcn ที่มีในโครงการ ไม่เพิ่มไลบรารีปฏิทินใหม่ ข้อมูลทั้งหมดมาจาก `trainer.slots` เดิม

### โครงสร้างเดสก์ท็อป

- ความกว้างสูงสุดประมาณ 56rem และความสูงไม่เกินพื้นที่จอ
- หัว Dialog แสดง “เลือกวันและเวลาฝึก” ชื่อเทรนเนอร์ และเขตเวลาไทย
- ฝั่งซ้ายเป็นปฏิทินรายเดือน มีชื่อเดือน ปุ่มเดือนก่อนหน้าและถัดไป และตารางเจ็ดวัน
- ฝั่งขวาแสดงเวลาว่างของวันที่เลือก
- ด้านล่างมีปุ่มรอง “ยกเลิก” และปุ่มหลัก “ยืนยันเวลานี้”

### สถานะปฏิทิน

- วันที่มี slot ว่างกดได้และมีตัวบอกจำนวนช่วง
- วันที่ไม่มี slot ว่างเป็น disabled
- วันที่เลือกใช้สี accent พร้อมข้อความหรือ `aria-pressed` ไม่พึ่งสีอย่างเดียว
- ปุ่มเดือนก่อนหน้าและถัดไป disabled เมื่อไม่มีเดือนที่มีข้อมูลให้ดู
- เมื่อเปิดใหม่ ให้แสดงเดือนของเวลาที่เลือกเดิม หรือเดือนแรกที่มี slot ว่าง

### การเลือกเวลา

- การกดวันที่เปลี่ยนเฉพาะรายการเวลาฝั่งขวา
- การกดเวลาเก็บเป็นค่าชั่วคราวใน Dialog
- ปุ่ม “ยืนยันเวลานี้” เปิดใช้งานเมื่อเลือกเวลาแล้ว
- การกดยืนยันเรียก `onSelectSlot` หนึ่งครั้ง ปิด Dialog และแสดงสรุปบนหน้าโปรไฟล์
- การกดยกเลิก กด Escape หรือคลิกพื้นหลังจะไม่เปลี่ยนเวลาที่เคยยืนยันไว้

## 6. ขั้นตอนการจอง

1. สมาชิกเปิด Dialog จาก “ดูตารางว่างทั้งหมด”
2. เลือกวันที่และช่วงเวลา
3. กด “ยืนยันเวลานี้”
4. Dialog ปิดและแผงจองแสดงวัน เวลา และปุ่ม “เปลี่ยนเวลา”
5. สมาชิกกด “จองเวลานี้” เพื่อไปหน้า `/booking`
6. สมาชิกตรวจรายละเอียดและยืนยันสร้างการจองจริง
7. ระบบเริ่มเวลา 10 นาทีหลังสร้างการจองสำเร็จเท่านั้น

URL เดิม `/booking?trainer=<slug>&slot=<id>` ต้องไม่เปลี่ยน และการตรวจ slot หมดอายุหรือถูกจองซ้ำในหน้าการจองยังทำงานตามเดิม

## 7. Responsive และการเข้าถึง

- ที่ 768px และต่ำกว่า Dialog เรียงปฏิทินกับรายการเวลาเป็นคอลัมน์เดียว
- ที่ 414, 375 และ 320px Dialog เว้นขอบจออย่างน้อย 1rem และเลื่อนภายในได้
- ปุ่มทุกตัวสูงอย่างน้อย 44px และข้อความบนปุ่มไม่ตัดเป็นสองบรรทัด
- Dialog ปิดได้ด้วย Escape ปุ่มปิด ปุ่มยกเลิก และคลิกพื้นหลัง
- เมื่อปิด Dialog โฟกัสกลับไปยังปุ่มที่ใช้เปิด
- เมื่อเปิด Dialog โฟกัสวันที่เลือกเดิม หรือวันแรกที่มีเวลาว่าง
- ทุกวันและเวลามีชื่อที่โปรแกรมอ่านหน้าจอเข้าใจได้
- focus ring แสดงทันทีและมี contrast เพียงพอ
- reduced motion ใช้การเปลี่ยน opacity แบบสั้น ไม่มีการเลื่อนหรือขยายเชิงพื้นที่
- หน้าและ Dialog ต้องไม่เกิด horizontal overflow ที่ 200% zoom

## 8. ข้อความในหน้าจอ

- ปุ่มเปิด: “ดูตารางว่างทั้งหมด”
- หัว Dialog: “เลือกวันและเวลาฝึก”
- คำอธิบาย: “เลือกวันที่ก่อน แล้วเลือกช่วงเวลาที่สะดวก”
- ปุ่มยืนยันใน Dialog: “ยืนยันเวลานี้”
- ปุ่มแก้ไขหลังเลือก: “เปลี่ยนเวลา”
- สถานะไม่มีข้อมูล: “ยังไม่มีเวลาว่างให้จอง”
- ข้อความกติกา: “เวลา 10 นาทีเริ่มหลังยืนยันการจองในขั้นตอนถัดไป”

ข้อความไม่กล่าวว่าเทรนเนอร์ต้องรับคำขอ และไม่กล่าวว่าการชำระหรือตรวจหลักฐานเป็นระบบอัตโนมัติ

## 9. การทดสอบ

Component tests ต้องครอบคลุมอย่างน้อย:

- เปิดและปิด Dialog จากปุ่มตารางว่าง
- จัดกลุ่ม slot ตามวันและเดือนถูกต้อง
- เลือกวันแล้วเห็นเฉพาะเวลาของวันนั้น
- ยืนยันเวลาแล้ว Dialog ปิด เรียก callback หนึ่งครั้ง และแสดงสรุปที่เลือก
- ปิดโดยไม่ยืนยันแล้วค่าเดิมไม่เปลี่ยน
- ไม่มี slot แล้วปุ่มเปิดและ CTA อยู่ในสถานะ disabled พร้อมเหตุผล
- ลิงก์ “จองเวลานี้” ใช้ trainer slug และ slot id เดิม
- Escape และการคืนโฟกัสทำงาน

Browser review ตรวจที่ 1280, 768, 414, 375 และ 320px รวมถึง keyboard, 200% zoom, reduced motion และ horizontal overflow โดยไม่เปลี่ยนข้อมูลในฐานข้อมูล

## 10. แนวทางการทำแบบสั้น

- ใช้ Dialog และ Button ที่มีอยู่แล้ว
- ใช้ `Intl.DateTimeFormat` และ `Date` ของเบราว์เซอร์
- สร้าง calendar grid จากข้อมูล slot เดิม
- ไม่เพิ่ม dependency, endpoint, table หรือ abstraction สำหรับอนาคต
- แก้เฉพาะคอมโพเนนต์ เทสต์ และ CSS ที่เกี่ยวข้องโดยตรง
